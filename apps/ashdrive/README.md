# ASHDRIVE — Shadow Sector

An open-world combat sandbox: pilot a remotely controlled armored motorcycle and freely explore a hostile industrial district. Start on the ground at the motorpool, choose your route through factory yards and elevated freeways, fight interceptor drones and gunships, and raid three defended relays. Recover their data and return to the motorpool extraction pad when ready.

An original open-source browser game built for the AI App Lab code-off, inspired by the military vehicle combat of 1995's Cyberbykes. Heavy red armor, exposed weapons, concrete freeways, smoke and olive transport craft establish the setting. All graphics and audio are generated by this project; no historical game assets are included.

## Play

| Control | Action |
| --- | --- |
| WASD / arrow keys | Throttle, reverse, steer |
| Space | Cannon |
| Shift | Turbo boost |
| Q | Guided missile |
| E | EMP |
| C | Cycle chase, cockpit, tactical camera |
| Tab / Map button | Tactical map; gameplay pauses while open |
| P | Pause / resume |
| M | Audio toggle |

Road lanes are optional routes through the district. Explore and approach objectives in any order, with no laps or race countdown. Destroy each relay with cannon fire or a missile, then drive within 10 meters of its dropped data case. Recover all three and return to the marked extraction pad where the mission started. Field supplies repair armor and replenish missiles. The **Autonomous Sortie** option demonstrates combat. The tactical map shows optional freeway routes, numbered relay status, enemies, your position and the motorpool extraction pad. Touch controls appear on supported small screens.

Rendering prefers **WebGPU**, with a **WebGL 2 fallback**. A modern browser with either backend is required; WebGPU normally requires HTTPS or localhost. Add `?renderer=webgl` to explicitly select the fallback. Audio starts after interaction. Once loaded, gameplay makes no external network requests; a first visit still needs the site's files.

## Graphics and performance

**Auto Quality** starts with a conservative rendering budget based on device capabilities, then adjusts to sustained frame rate. Performance and Balanced tiers lower resolution and remove bloom and shadows; High Detail enables those effects. Auto can reach an additional Ultra tier when there is sustained headroom. Under sustained load, Auto can reduce resolution in additional steps down to 35%, then restore it gradually when frame rate recovers. The HUD reports measured FPS and rendering scale.

Use the in-game graphics selector to choose **Auto Quality**, **High Detail**, **Ultra Detail**, **Balanced**, or **Performance**. Manual choices stay fixed. Auto waits before increasing detail and avoids quickly retrying a tier that slowed the game down. Browser size, device pixel ratio and a pixel budget limit the actual resolution, so the displayed percentage can be lower than a tier's cap.

For a reproducible launch, URL overrides are supported: `?quality=low`, `?quality=medium`, `?quality=high`, `?quality=ultra`, or `?quality=auto`. Combine renderer and quality options as `?renderer=webgl&quality=low`. Performance still depends on the device and other active applications.

## Standalone development

Requires Node.js 22.12 or newer. In an exported or cloned standalone repository:

```sh
npm ci
npm run dev
```

Verify gameplay math and create the static production build:

```sh
npm run test:unit
npm run build
npm run preview
```

`dist/` contains the full static site. The unit tests exercise gameplay calculations; they do not replace interactive browser testing. GitHub Actions runs unit tests and the production build on pushes and pull requests.

## Shared AI App Lab development and release export

The lab uses one root dependency installation. Do not create package.json or node_modules inside this app folder. From the lab root:

```sh
npm run dev
npm run show ashdrive
node --test apps/ashdrive/tests/*.test.js
node apps/ashdrive/release.mjs /tmp/ashdrive-release
cd /tmp/ashdrive-release
npm install
npm run test:unit
npm run build
```

The exporter copies this game's source and pure unit tests, generates an MIT package with pinned installed dependency versions, and includes GitHub Actions and Cloudflare settings. Browser specs depend on the lab fixture and are excluded. The lab navigation link becomes a GitHub source link. An ownership manifest removes files from earlier exports when they disappear from the app, while retaining `.git`, installed dependencies, package-lock.json and unrelated local files. Re-export after game changes and run the release checks again. Commit package-lock.json with the exported source. The exporter itself remains in the lab.

To build this app directly using shared dependencies:

```sh
npx vite build --config apps/ashdrive/standalone.vite.config.js
```

## Public GitHub and Cloudflare Pages release

The intended public source repository is `mvalancy/ashdrive`. Preparing an export does not create the repository or deploy a site. After review, publication from the standalone directory can use:

```sh
git init -b main
git add .
git commit -m "Release ASHDRIVE Shadow Sector"
gh repo create mvalancy/ashdrive --public --source=. --remote=origin --push
```

For an existing repository, commit and push updates normally instead. Review `git diff --cached` before the first commit; only the game and release files belong in this public repository.

Connect that repository to a new Cloudflare **Pages** project using the Git integration:

| Setting | Value |
| --- | --- |
| Production branch | `main` |
| Root directory | repository root |
| Build command | `npm run build` |
| Build output directory | `dist` |
| Node.js | `22` from `.node-version` |

The game needs no environment secrets, database, server functions or runtime API keys. Cloudflare account access and permission to connect the GitHub repository are needed to create the project. Once connected, pushes to `main` rebuild the site; Cloudflare supplies its actual public URL after deployment. `wrangler.toml` declares the Pages output directory, and `public/_headers` supplies static asset caching and basic response headers.

Prefer Git integration for this project. If using a separate direct-upload Pages project, an authenticated Wrangler installation can deploy the already built `dist/` directory with `wrangler pages deploy dist --project-name ashdrive`. This command publishes the site; it is not part of the preparation script.

Official documentation: [Vite on Pages](https://developers.cloudflare.com/pages/framework-guides/deploy-a-vite3-project/), [build settings](https://developers.cloudflare.com/pages/configuration/build-configuration/), [Wrangler Pages commands](https://developers.cloudflare.com/workers/wrangler/commands/pages/).
